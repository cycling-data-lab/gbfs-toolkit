    aggregate: 15 minutes, an hour, a day¶

    Experimental

    Part of the experimental data-lake modules (2.1.0). See the overview.

    aggregate_availability turns minute-level snapshots into a station-by-bucket table whose columns mean the same thing every time. The definitions are fixed:

    Column Definition
    n_obs rows in the bucket, all of them (nothing is dropped or de-duplicated)
    n_valid rows with a bike count that are not flagged both_zero_suspect; every other column is computed from these
    bikes_mean, bikes_min, bikes_max, bikes_first, bikes_last the bike count over the valid rows, first and last in time order
    docks_mean, docks_min the same for free docks (empty if the operator does not publish them)
    pct_empty share of valid rows with no bike, in %
    pct_full share of valid rows where the station is full, in %: no free dock, or, if docks are not published and a capacity column exists, bikes at or above capacity
    pct_renting share of valid rows where is_renting is true, in %
    pct_both_zero share of all rows flagged both_zero_suspect, in % (counted here, excluded elsewhere)
    movement_volume sum of the absolute changes of the bike count between two consecutive valid rows of a station at most max_pair_gap (90 s) apart, in the bucket of the second

    movement_volume estimates how many bikes moved. A rental and a return within one poll cancel out and are invisible, and it is not a count of trips.

    The conservation check¶

    The sum of n_obs over all buckets is the number of input rows, at every frequency. This is the property that makes the three levels describe the same data, and aggregate_levels verifies it for you (check_conservation does it by hand).

    Buckets are aligned on UTC. With tz (an IANA zone, or {system_id: zone}), the local wall-clock start of each bucket and its UTC offset are added, so a local-time analysis can group on them without redoing the clock change.

    Large volumes¶

    Besides a pandas frame, aggregate_availability, aggregate_levels and check_conservation take an Arrow table or dataset, a DuckDB relation, or a path: a lake written by store, a folder of Parquet files (the day files and fragments of collect included), a file or a glob. The source is not loaded whole.

    engine= What computes Memory
    "auto" (default) a pandas frame stays on pandas; any other source goes to DuckDB if the duckdb extra is installed, otherwise to the pandas windows below see below
    "duckdb" one SQL query over the source (windows, aggregates), spilling to a temporary folder bounded by DuckDB (GBFS_TOOLKIT_DUCKDB_MEMORY_LIMIT=4GB caps it)
    "pandas" window by window (chunk=, one day by default, rounded up to a multiple of freq so that no bucket is split), carrying each station's last row across a boundary so the movement_volume of a pair that straddles two windows is kept one window

    The engines agree: n_obs is conserved by each, counts and integer columns are identical, and the other columns differ by floating-point rounding at most. Tests compare them on random data (including repeated instants, missing counts and windows that cut a pair of rows). Two rows of the same station at the same instant are ordered as the source lists them. The time column of a table, relation or path must be a timestamp.

    Measured on a synthetic lake of 42 million rows (1000 stations, one poll a minute, 30 days; a laptop with 16 logical CPUs, DuckDB capped at 6 GB): the three levels take 72 s with DuckDB, and 190 s window by window in pandas with about 2 GB; a pandas frame of just two days of that lake (2.9 million rows) already peaks at 6 GB. benchmarks/lake_volume.py reproduces the measure and benchmarks/README.md has the table.

    Example¶

    import numpy as np
import pandas as pd

from gbfs_toolkit.aggregate import aggregate_availability, aggregate_levels, check_conservation

rng = np.random.default_rng(1)
t = pd.date_range("2026-03-28T22:00Z", periods=6 * 60, freq="min")   # spans Paris's clock change
snapshots = pd.DataFrame({
    "system_id": "demo", "station_id": "s1", "fetched_at": t,
    "num_bikes_available": rng.integers(0, 15, len(t)),
    "num_docks_available": rng.integers(0, 15, len(t)),
})

hourly = aggregate_availability(snapshots, "1h", tz="Europe/Paris")
print(hourly[["bucket_start_utc", "bucket_start_local", "utc_offset_min", "n_obs", "bikes_mean"]].head(4))

levels = aggregate_levels(snapshots)                  # 15m, 1h, 1d; each one checked
print({name: int(table["n_obs"].sum()) for name, table in levels.items()})
check_conservation(levels["15m"], snapshots)          # raises if an observation went missing

# The same table from an Arrow table, by windows of two hours (what runs without DuckDB)
import pyarrow as pa

table = pa.Table.from_pandas(snapshots, preserve_index=False)
by_windows = aggregate_availability(table, "1h", tz="Europe/Paris", engine="pandas", chunk="2h")
pd.testing.assert_frame_equal(hourly, by_windows, check_exact=False)

    API¶

    aggregate ¶

    Station availability aggregated to 15 minutes, an hour or a day, with fixed definitions.

    Experimental

    Part of the experimental data-lake modules added in 2.1.0: names, parameters and output columns may change in a minor release (see the API policy).

    Minute-level snapshots are too many to plot or to join; what an analysis usually needs is a station-by-bucket table whose columns mean the same thing every time. aggregate_availability produces one, with these definitions (they will not change silently):

    n_obs rows in the bucket, all of them. Nothing is dropped or de-duplicated here, so the sum of n_obs over all buckets is the number of input rows, at every frequency (check_conservation verifies it, and aggregate_levels does it for you); n_valid rows that carry a bike count and are not flagged both_zero_suspect (see gbfs_toolkit.quality): the observations every other column is computed from; bikes_mean, bikes_min, bikes_max, bikes_first, bikes_last the bike count over the valid rows (first and last in time order); docks_mean, docks_min the same for free docks (missing when the operator does not publish them); pct_empty share of valid rows with no bike, in %; pct_full share of valid rows where the station is full, in %: no free dock, or, when docks are not published and a capacity column exists, bikes at or above the capacity; pct_renting share of valid rows where the station is renting, in %; pct_both_zero share of all rows flagged both_zero_suspect, in % (counted here, excluded elsewhere); missing if the frame carries no such column; movement_volume sum of the absolute changes of the bike count between two consecutive valid rows of the same station that are at most max_pair_gap (90 s) apart, attributed to the bucket of the second. It estimates how many bikes moved; a rental and a return inside one poll cancel out and are invisible. It is a volume of movement, not a count of trips.

    Buckets are aligned on UTC. With tz, the local wall-clock start of each bucket and the UTC offset are added, so a local-time analysis can group on them without recomputing the clock change.

    Examples:

    >>> import pandas as pd
>>> from gbfs_toolkit.aggregate import aggregate_availability
>>> t = pd.date_range("2026-03-01T08:00Z", periods=30, freq="min")
>>> snaps = pd.DataFrame({
...     "system_id": "demo", "station_id": "s1", "fetched_at": t,
...     "num_bikes_available": range(30), "num_docks_available": range(30, 0, -1)})
>>> agg = aggregate_availability(snaps, "15min")
>>> agg["n_obs"].tolist(), agg["bikes_first"].tolist(), agg["bikes_last"].tolist()
([15, 15], [0, 15], [14, 29])
>>> int(agg["n_obs"].sum()) == len(snaps)
True

    def aggregate_availability(
    df: Any,
    freq: str = "15min",
    *,
    tz: str | Mapping[str, str] | None = None,
    max_pair_gap: str | pd.Timedelta = "90s",
    time_col: str = "fetched_at",
    engine: str = "auto",
    chunk: str | pd.Timedelta = "1D",
) -> pd.DataFrame:
    """Aggregate station-status rows to buckets of ``freq`` (see the module for the definitions).

    Parameters
    ----------
    df : pandas.DataFrame, pyarrow.Table, duckdb relation, str or Path
        One row per station per poll: ``system_id``, ``station_id``, ``time_col`` and
        ``num_bikes_available``; optionally ``num_docks_available``, ``is_renting``,
        ``capacity`` and ``both_zero_suspect``. Duplicated rows are counted; de-duplicate
        first if your source can repeat a poll. Besides a pandas frame, an Arrow table or
        dataset, a DuckDB relation or a path (a lake written by `gbfs_toolkit.store`, a
        folder of Parquet files, a file or a glob) is read without loading it whole; the time
        column of those must be a timestamp.
    freq : str, default "15min"
        A fixed-width frequency: ``"15min"``, ``"1h"``, ``"1D"`` or any other.
    tz : str or mapping, optional
        An IANA zone, or ``{system_id: zone}``, for the local columns.
    max_pair_gap : str or Timedelta, default "90s"
        Longest time between two rows still counted as consecutive for ``movement_volume``.
    engine : {"auto", "duckdb", "pandas"}, default "auto"
        Who computes. A pandas frame stays on pandas under ``"auto"``; any other source goes
        to DuckDB when the ``duckdb`` extra is installed and is otherwise processed window by
        window in pandas (``chunk`` wide), so the memory used is one window, not the table.
        The engines agree: counts and integer columns are identical and the other columns
        differ by floating-point rounding at most (``n_obs`` is conserved by each). Rows with
        the same station and the same time are ordered as the source lists them.
    chunk : str or Timedelta, default "1D"
        Width of a window of the pandas engine on a table, an Arrow dataset or a path (rounded
        up to a multiple of ``freq``, so that no bucket is split).

    Returns
    -------
    pandas.DataFrame
        One row per (system, station, bucket) that has at least one row, sorted; columns as in
        `AGGREGATE_COLUMNS`.

    Raises
    ------
    ValueError
        For a calendar frequency (``"1ME"``), an unparseable time, an unknown ``engine`` or,
        for a table, a time column that is not a timestamp.

    Examples
    --------
    >>> import pandas as pd
    >>> t = pd.to_datetime(["2026-03-01T08:00Z", "2026-03-01T08:01Z", "2026-03-01T08:02Z"])
    >>> df = pd.DataFrame({"system_id": "a", "station_id": "s", "fetched_at": t,
    ...                    "num_bikes_available": [5, 3, 4]})
    >>> row = aggregate_availability(df, "1h").iloc[0]
    >>> int(row["n_obs"]), float(row["bikes_mean"]), int(row["movement_volume"])
    (3, 4.0, 3)
    """
    table = open_table(df, what="aggregate_availability")
    need_columns(
        pd.DataFrame(columns=table.columns()),
        [*_REQUIRED[:2], time_col, _REQUIRED[2]],
        what="aggregate_availability",
    )
    step = fixed_timedelta(freq, what="freq")
    gap = fixed_timedelta(max_pair_gap, what="max_pair_gap")
    window = fixed_timedelta(chunk, what="chunk")
    use = resolve_engine(engine, table, what="aggregate_availability")
    if use == "duckdb":
        out = _duckdb_aggregate(table, step, gap, time_col)
    elif table.kind == "pandas":
        out = _bucketed(table.df, step, gap, time_col, None)[0]  # type: ignore[attr-defined]
    else:
        out = _chunked_aggregate(table, step, gap, time_col, window)
    out = _finish(out, tz)
    _log.info("aggregate: %d rows -> %d buckets of %s (%s)", table.count(), len(out), freq, use)
    return out

    def check_conservation(aggregated: pd.DataFrame, source: Any) -> None:
    """Raise ``GBFSValidationError`` unless the buckets hold exactly the source rows.

    The sum of ``n_obs`` must equal the number of rows of ``source`` (a frame, an Arrow
    table, a relation or a path): an aggregate that lost or invented an observation is wrong
    whatever its means look like.

    Examples
    --------
    >>> import pandas as pd
    >>> check_conservation(pd.DataFrame({"n_obs": [15, 15]}), pd.DataFrame({"x": range(30)}))
    """
    got, want = (
        int(aggregated["n_obs"].sum()),
        open_table(source, what="check_conservation").count(),
    )
    if got != want:
        raise GBFSValidationError(
            f"aggregation does not conserve observations: sum of n_obs is {got}, source has {want} rows"
        )

    def aggregate_levels(
    df: Any,
    *,
    levels: Mapping[str, str] | None = None,
    verify: bool = True,
    **options: object,
) -> dict[str, pd.DataFrame]:
    """The 15-minute, hourly and daily aggregates in one call, each checked for conservation.

    Returns ``{"15m": ..., "1h": ..., "1d": ...}`` (or the ``levels`` you give, name -> freq);
    ``options`` go to `aggregate_availability` (``engine``, ``tz``, ``chunk``...). With
    ``verify`` (the default) each level must conserve the observations, so the three tables
    describe the same rows.

    Examples
    --------
    >>> import pandas as pd
    >>> t = pd.date_range("2026-03-01T00:00Z", periods=200, freq="min")
    >>> df = pd.DataFrame({"system_id": "a", "station_id": "s", "fetched_at": t,
    ...                    "num_bikes_available": 3})
    >>> out = aggregate_levels(df)
    >>> {k: int(v["n_obs"].sum()) for k, v in out.items()}
    {'15m': 200, '1h': 200, '1d': 200}
    """
    source = open_table(df, what="aggregate_levels")
    result = {}
    for name, freq in (levels or LEVELS).items():
        agg = aggregate_availability(source, freq, **options)  # type: ignore[arg-type]
        if verify:
            check_conservation(agg, source)
        result[name] = agg
    return result
